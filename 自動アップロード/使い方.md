# 自動アップロードの使い方

作業の場（Cowork の会話）からプロジェクトのフォルダーに置いたものを、あきさんの操作なしで GitHub に上げる仕組み。どのプロジェクトのフォルダーでも同じものを使える。

## 仕組み
1. 作業の場が、フォルダーにファイルを置く。ソースは `<名前>-source.tar.gz`（中身は `<名前>/` で始まる）として置く。例: `app-source.tar.gz` → `app/`
2. 最後に `push-request.txt` を置く。1行目がコミットの説明になる
3. Mac の launchd がそれに反応して `自動アップロード/auto-push.sh` を動かす。tar を展開し、コミットして push する
4. 結果は `auto-push.log` に追記される。作業の場はこのログで成功を確かめる

## 新しいプロジェクトで使い始めるとき（一度だけ）
1. GitHub に空のリポジトリを作る。fine-grained token の「Repository access」にそのリポジトリを入れ、「Contents」を「Read and write」にする
2. 作業の場に、プロジェクトのフォルダーへ `自動アップロード/`（auto-push.sh と install.sh）を置いてもらう
3. ターミナルで次を一度だけ実行する

```
sh ~/<フォルダー名>/自動アップロード/install.sh https://github.com/asatoh412-spec/<リポジトリ名>.git
```

最初の push のときだけ、ユーザー名（asatoh412-spec）とトークンを聞かれる。トークンはこのリポジトリ専用に保存されるので、ほかのプロジェクトのトークンと取り違えない。

## 街歩き謎解きについて
「街歩き」フォルダーは、先に jp.aki.machiaruki.autopush という名前で導入済み。install.sh を実行し直す必要はない（実行しても、同じフォルダーをもう一つの名前で見張るだけで害はないが、二重になるので不要）。

## 止める・やめる
- 止める: `launchctl unload ~/Library/LaunchAgents/<項目名>.plist`（項目名は install.sh の最後に表示される。街歩きは jp.aki.machiaruki.autopush）
- うまく上がらないとき: `auto-push.log` の最後を見る。403 はトークンの権限不足（Repository access と Contents を確認）
