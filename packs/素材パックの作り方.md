# 素材パックの地点の書き方（街歩き謎解き、形式 machiaruki-pack/1）

## アプリの前提
- 個人用の街中オリエンテーリングのアプリ。謎を読んで地点を探し、着くと解説が出る。学びの中心は解説で、謎は動機付け。難しすぎないこと
- 地図には地区の範囲だけを出し、地点の正確な位置は出さない。ヒントを使うと範囲が狭まる
- 到着は位置情報で判定（半径50m）。着いたら答えを入力する。表記ゆれ（漢字・かな・旧字体）は許容する
- 謎の難しさは「ふつう」1種類

## 地点1件の JSON
```json
{
  "id": "shinjuku-<最初のレコードのID>",
  "name": "地点の名前（現地や区の資料での表記）",
  "kana": "ひらがな読み",
  "lat": 35.0, "lon": 139.0,          // 区データの値をそのまま使う
  "address": "所在地",
  "kind": "寺社|碑・石造物|旧居跡|史跡|墓|樹木|建造物|博物館",
  "indoor": false,                     // 中に入って温まれるなら true（博物館、本堂に上がれる寺など）
  "access": "境内に入れる時間や休館日など、訪問の制約。出典で確認できなければ null",
  "seasonal": [ { "months": [11,12], "note": "見どころ（出典があるものだけ）" } ],
  "riddle": "謎の文。地点の歴史・由来に関係する内容にする。地点名そのものや住所は書かない。2〜3文",
  "hints": [
    { "text": "ヒント1（大まか。どの町・どの坂の近くかなど）", "radius_m": 500 },
    { "text": "ヒント2（中くらい。目印や向き）", "radius_m": 250 },
    { "text": "ヒント3（ほぼ答え）", "radius_m": 100 }
  ],
  "answer": {
    "prompt": "何を入力するかの問い（例：この寺の名前は？／ここに暮らした作家の名前は？）",
    "display": "正解の表記",
    "accept": ["正解の表記", "ひらがな", "通称", "旧字体", "…"],
    "basis": "地点名" または "現地表示"
  },
  "onsite": "現地で見えると出典で確かめられるもの（説明板、石碑、山門など）。確かめられなければ null",
  "short": "正解後に出す短い解説。80〜140字",
  "long": "詳しい解説。400〜800字。出典で裏付けできる事実だけ",
  "sources": [
    { "title": "ページや資料の名前", "publisher": "新宿区 など", "url": "https://...", "kind": "自治体|教育委員会|寺社|観光協会|文献|Wikipedia|その他", "accessed": "2026-11-11" }
  ],
  "status": "unverified",
  "notes": "作成者から確認担当へのメモ（食い違い、確認できなかった点など）。なければ空文字"
}
```

## 規則
1. 事実（年号・人物・由来）は sources にあるものだけを書く。新宿区の文化財データの「説明」は一次出典として必ず sources に入れる（title は「新宿区の文化財一覧（オープンデータ）」、publisher「新宿区」、url は https://www.city.shinjuku.lg.jp/content/000399966.csv 、kind「自治体」）。区のデータに URL 列があればそれも入れる
2. 区のデータ以外の事実を書くときは、ウェブ検索で実際にページを開いて確かめ、そのページを sources に入れる。検索結果の要約だけを根拠にしない。優先順は 自治体・教育委員会 > 寺社の公式 > 観光協会 > 文献 > Wikipedia
3. 確かめられないことは書かない。食い違いがあれば notes に書く
4. answer.basis は原則「地点名」。地点名で答えさせるのが不自然なとき（旧居跡など）は、出典で確かめられる人名などを答えにして basis を「地点名」とする。現地の碑文や表示の文字を答えにするのは、その文字が出典（写真付きの公式ページなど）で確かめられるときだけで、そのとき basis を「現地表示」にする
5. 謎は答えをそのまま書かない。知識がなくても、ヒントと現地の様子で解けるようにする。例：「大名が犬のために作らせた施設の跡を示す碑を探せ」
6. 同じ場所に複数の文化財があるとき（records が複数）は1地点にまとめ、解説で両方に触れる
7. 個人宅が所有者の旧居跡は、敷地に入らず道から説明板を見る前提で書く。access に「個人宅。道路から見る」と書く
8. 墓は、墓所の場所を明かさない寺もあるので、境内の参拝が可能か出典で確かめ、access に書く。確かめられなければ notes に書く
9. 日本語で書く。中国語の字形を混ぜない

## 出力
入力ファイルの各地点について上の JSON を1件ずつ作り、JSON 配列として指定のファイルに書き出す。書き出したら python3 -m json.tool で壊れていないか確かめる。
